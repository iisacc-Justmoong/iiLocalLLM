# GGUF 도구 예시 템플릿의 호환성

일부 GGUF의 Jinja 문자열에는 도구 호출의 예시 객체 중괄호가 두 번 이스케이프되어
실제 프롬프트에 `{{"name": ...}}`가 나타난다. 기본 내장 템플릿을 선택할 때 이
정확한 placeholder 예시만 단일 JSON 객체 형태로 정규화한다.

모델 파일과 검증 해시, 입력 메시지, 사용자 본문의 중괄호, 올바른 Jinja 변수,
명시적으로 선택한 chat_template는 변경하지 않는다. 보정할 내용이 없는 모델은
기존 내장 템플릿 선택 경로와 보조 tool-use 템플릿을 그대로 사용한다.
도구 권한·인자 검증과 생성 토큰·문맥 한도에도 영향을 주지 않는다.

`iiLocalLLM.tool_template_contract`는 잘못된 예시의 보정, 멱등성과 올바른
Jinja·도구 JSON의 보존을 검증한다. 실제 모델 검사는 같은 GGUF를 사용한다.
## 단일 도구 턴의 종료

명시적인 required 단일 JSON 도구 턴은 완성된 `<tool_call>...</tool_call>` 경계에서 실행기에 제어를 반환한다. 모델이 도구 응답을 받기 전에 그 뒤로 추측 답변을 계속 생성하여 출력 한도를 소진하는 문제를 방지한다. 완성된 JSON 객체, 공개된 도구 이름 및 객체 형식 arguments를 확인하며, 문자열 인자 안에 들어 있는 종료 태그나 불완전한 JSON은 종료로 인정하지 않는다. 템플릿이 미리 제공한 시작 태그도 처리한다.

최대 토큰 수, 컨텍스트 크기, 취소와 기존 최종 인자 검증은 그대로 유지한다. 부분 JSON을 허용하거나 토큰 한도에 도달한 출력을 사후 승인하는 방식이 아니다. 다른 템플릿 형식과 병렬 호출의 EOS 처리는 보존한다. tool_turn_contract와 기존 실제 추론 검사가 이 경계를 검증한다.




명시적인 required 단일 호출에서는 신뢰된 JSON 태그 템플릿의 시작 태그를 assistant prefill에 넣고 모델 입력·문법 상태·파서 상태에 동일하게 반영한다. 필수 호출 앞에 자유로운 설명을 끝없이 생성할 수 없게 하되, 도구 이름과 모든 인자는 모델이 생성하고 기존 검증을 거친다. 미리 넣은 태그도 입력 토큰으로 계산하며 컨텍스트·출력 한도를 늘리지 않는다. auto 호출, XML 인자 템플릿, 활성 사고 모드와 병렬 호출의 동작은 보존한다. native_grammar의 requiredJsonToolPrefillStartsInsideTheCallEnvelope가 빈 인자 도구와 설명문 거부를 검증한다.
